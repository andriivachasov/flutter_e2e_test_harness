Goal: Flexible and reliable e2e test harness for flutter applicaitons with both android and ios support. It is to be used as an instruction for AI agents to integrate it into an existing application, not human.

Requirements:
 - Support for both Android and iOS platforms
 - Backend-agnostic. Assume simple API (http/1+json) communication is used.
 - Flexible test structure allowing for easy maintenance and extension
 - Reliable test execution with comprehensive error handling
 - Integration with Flutter's testing framework
 - Advanced observability - all test runs must produce screenshots, video recordings and test/app/backend logs. The structure must be readable and clean for a human to verify test runs, even successful. 
 - Test must run fully locally. The apps must run on ios simulators\android emulators against a local backend instance.
 - The harness must provide a working and verified example of an e2e test, so it must implement a simple backend and app to test.
 - The recommendations must include flows that imply on resetting user state and data cleanup.
 - Tests must be modular, so that a feature test that implies on signing in uses the sign in test module and then execute the actual feature test.
 - Provide a solution (or several solutions) for the test user management - e.g. create a new user each test run OR have a pool of test users with proper user data cleanup. The solutions must assume that firebase auth is used.
 - The harness must support parallel test execution to test user interaction flows - e.g. UserA and UserB signed in, UserA sends a message and UserB receives it. The interaction for the example may be different for simplicity, but the whole approach must be scalable enough to cover pairing flows, tight user interactsions etc.
 - Make sure to consider data seeding for complex tests.
 - The harness must be able to run a signle test as well as all test flows.
 - The harness must include self-audit tools to assess reliability, performance etc.
